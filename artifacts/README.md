# Published artifact sources

The HTML behind every artifact published for this project. **Kept in the repo on
purpose** — these cost real tokens to write, and a session scratchpad is wiped when the
session ends.

`artifacts/` used to be in `.gitignore` (line 44, inherited from the scaffold, right under
`.env*`). That is now explicitly negated — if you ever regenerate `.gitignore` from a
template, check that these do not silently stop being tracked.

## The files are publish-ready, not standalone

Each file deliberately has **no** `<!doctype>`, `<html>`, `<head>` or `<body>` tag. The
Artifact tool wraps them at publish time and refuses them otherwise. Browsers infer the
missing tags, so double-clicking one still renders it correctly for a quick look.

## Updating a published artifact

Publish with the **`url`** of the existing artifact, not just the file path. Publishing
without it creates a *second* artifact at a new URL instead of updating the one people
already have a link to.

Read the live version first (`action: "read"` with that url) and build the update on what
comes back — a publish to an artifact the current session has not read or published is
refused.

## The owner pitch (3 pages, non-technical)

Written for Jennifer and Brian, who do not work in tech. Every technical word gets an
"In plain terms" card with an everyday analogy — that device is the whole point of the
set, so keep it if these are edited. Screenshots are embedded as data URIs rather than
uploaded assets, so each page is self-contained and needs no capability.

Option A is slate blue and Option B is Thai-tea orange, consistently across all three,
so the colour alone tells the reader which option a paragraph is about.
