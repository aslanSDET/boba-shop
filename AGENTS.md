# Working in this repo

Everything below is hand-written and belongs to the project. The block above is
generated by `next dev` between its own markers — leave it alone, and never put
project rules inside it, because they will be overwritten.

## What this is

Direct-ordering websites for small independent restaurants, so they keep the
customers and the margin that DoorDash and Uber Eats currently take. One repo,
several restaurants, **one deployment each**.

- **Snowdaes** — Billerica & Lowell MA, Clover. Working against Clover's sandbox.
- **Asian Kitchen** — Birmingham AL, Square. Front end only; no POS is wired.

`README.md` has the run commands and the directory map. Read `PLATFORM.md`
before changing anything structural — it records decisions that look arbitrary
until you know the reasoning.

## Invariants — breaking one of these is a bug, not a style choice

1. **Restaurants share nothing.** No import may cross between
   `src/restaurants/<a>/` and `src/restaurants/<b>/`. If two restaurants need the
   same thing, copy it. Extraction waits for a third case (`PLATFORM.md` §3).

2. **`src/app/` holds routes and nothing else.** Every file there is a thin shim
   that names a URL and renders something from `src/restaurants/`. No menu data,
   no components, no logic. Next forces routes to live here; that is the only
   reason the directory exists.

3. **The root layout and `globals.css` stay impersonal.** No fonts, no palette,
   no shop name. Both restaurants load them, so anything with personality leaks.
   Each restaurant paints its own ground in its own `theme.css`.

4. **The POS is the calculator.** Never compute a total or a tax and send it to
   Clover. Build the order from the merchant's own inventory and read the total
   back. Cart figures are a labelled preview. Two calculators drift, and the
   shop's till is the one that has to be right.

5. **One restaurant per deployment.** `RESTAURANT` is read once in
   `src/restaurants/active.ts`. Do not add per-request restaurant lookup.

## Hard rules

- **This is a public GitHub repo.** No token, key, or merchant id in a commit, a log line, a script argument, or a scratch file inside the repo. Credentials live in `.env.local`, which is gitignored.
- **`CLOVER_ENV=sandbox` is the default and stays that way.** `guardProductionWrite()` refuses non-GET requests against production; do not weaken it. A production write puts paper in a working kitchen.
- **Sandbox orders are real objects.** Creating them during testing is fine; leaving them behind is not. Delete what you created, and never delete an order that has a payment on it.
- **Do not install third-party Clover or Square MCP servers.**

## Conventions

- **Comments explain why, not what.** The interesting files here carry the measurement or the trap that shaped them — Clover's `taxAmount` reading `$0.00` on every order, `mount()` needing a CSS selector, a `leading-[1.1]` box shearing descenders. Keep that; it is the part that saves the next person a day.
- **Measure before claiming.** Much of `scripts/spike/findings.md` exists because the documentation was wrong. If you assert an API behaves a certain way, say whether you observed it or read it.
- **Generated files are generated.** `src/restaurants/snowdaes/menu.*.generated.ts` comes from `scripts/import-menu.mjs`. Edit the script, not the output.
- **Verify in a browser, not just in `tsc`.** A green build has repeatedly hidden a page that did not render.
